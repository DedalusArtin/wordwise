# WordWise

> 基于本地 LM Studio 大模型能力的**可视化背单词 + AI 讲解**一体化桌面软件

<p align="left">
  <img alt="Rust" src="https://img.shields.io/badge/Rust-1.77%2B-orange?logo=rust">
  <img alt="Tauri" src="https://img.shields.io/badge/Tauri-v2-24C8DB?logo=tauri">
  <img alt="Platform" src="https://img.shields.io/badge/Platform-Windows%2010%2F11-blue">
  <img alt="License" src="https://img.shields.io/badge/License-MIT-green">
</p>

WordWise 把「背单词」和「AI 讲解」放进同一个窗口：左边是干净的词条，
右边是本地大模型逐字写出的讲解；答错的词会自己钻进错词本，
并按遗忘曲线准时回到你眼前。

整个前端仅用原生 HTML/CSS/JS（无 node_modules），后端 Rust + Tauri，
安装包不到 10 MB，启动即用。

## 功能总览

| # | 需求 | 实现情况 |
|---|---|---|
| 1 | **双向背诵模式** | 看英文选中文 / 看中文选英文，一键切换，键盘 A-D 可选答 |
| 2 | **内置搜索引擎 + 联网查词** | 4 个公开词典源并行聚合 + 输入联想 + 维基百科知识；断网时由本地大模型兜底生成 |
| 3 | **记忆辅助内容可选开关** | 音标 / 变形 / 例句 / 相关词 / 词根记忆法 / 答错弹卡 / AI 讲解，共 7 个独立开关，实时联动 |
| 4 | **遵循遗忘规律动态排程** | SM-2 改良算法 + 可配置记忆周期表（8 档间隔）；读取系统时间计算下次复习点，逾期优先、常错优先 |
| 5 | **常错词自动强化 + 详情卡** | 错误率超阈值自动进入强化队列；答错弹出仿有道词典的完整详情卡（5 个标签页） |
| 6 | **小语种可扩展** | 词典源 = URL 模板 + JSON 字段路径映射，纯配置接入新语言，内置源本身即是范例 |
| 7 | **可长期挂起的侧边栏** | 独立置顶窗口，托盘一键唤出，支持查词与单题快测；关闭主窗口后仍常驻 |
| 8 | **打包与自动上传** | Inno Setup 中文安装程序（可选保留学习数据）；`scripts/upload_github.py` 读取 hermes 中已保存的 token 自动建仓推送 |

### 额外增强

- **互译方向选择器**：顶部「源语言 ⇄ 目标语言」一键互换，查词页与翻译页共用同一份方向，切换后两个页面的占位提示、查询请求与返回语言同步生效
- **独立翻译栏目**：左右分栏 + 实时翻译 + 复制 / 朗读 / 收藏 / 历史记录，支持句子与段落；在线引擎限频时自动降级本地大模型
- **翻译 AI 增强**：AI 释义与语境说明、多版本译文、自动润色、例句生成
- **AI 流式讲解**：打字机效果逐字输出，支持追问（「这个词和 rely 有什么区别？」）。
  讲解会**自动存档**，第二次点开直接读本地（不花算力），并可一键**并入词库**变成可背的词条
- **查词判定不依赖 AI**：只要有一个词典源返回结果就算成功；AI 没开只会在结果上方留一条提示条，不会变成「查询失败」
- **解析走三级阶梯**：匹配式（字段映射）→ 启发式（看内容不看字段名）→ 纯文本（HTML 页面），上游改版也不会「连得上却查不出」
- **词条详情卡**：释义 / 变形 / 例句 / 相关词 / AI 讲解 五个标签页，仿有道词典视觉
- **知识图谱（独立栏目）**：把词与词的关系画成一张可缩放、可拖拽的力导向图。6 类关系各有配色；词库里写明的关系画**实线**，AI 推测的画**虚线**；点节点以它为中心展开，双击看释义或去查词
- **学习统计**：14 天答题柱状图 + 掌握度**环形图**（中心显示总量）、连续学习天数、正确率
- **复习计划视图**：「现在该背哪些」到期清单（逾期最久的排最前）+ 未来 14 天到期量可视化 + 记忆周期表图示
- **错词本多维筛选**：按错误次数 / 错误率 / 掌握度筛选，5 种排序；一键导出 **Markdown**（给人看）或 **CSV**（给 Excel / Anki 用）
- **演示模式**：设置里打开后，统计 / 计划 / 错词本 / 图谱填充一份示例数据，**不写入数据库**，顶部有常驻横幅提示
- **数据库维护面板**：显示 SQLite 文件的路径、体积、每张表多少行；一键**整理**（VACUUM 回收空洞）、**完整性检查**、**备份**（`VACUUM INTO` 一致性快照）
- **存放位置自己说了算**：数据默认**跟着软件走**（装到 D 盘，词库和模型就都在 D 盘，不写 C 盘）；设置页里能看到数据 / 模型 / 引擎各在哪、各占多少、**每个盘还剩多少**，并且可以把数据目录或模型目录换到别的盘（可选把现有文件一起搬过去，源文件不删）
- **AI 服务随便挑**：三种来源一键切换 —— 程序自带的**本机一键部署**、你已有的 **LM Studio**、或**在线 API**（内置 DeepSeek / 通义千问 / Kimi / 智谱 GLM / 硅基流动 / OpenRouter / OpenAI 预设，也可填任意 OpenAI 兼容地址）。同一套界面管地址、模型名、**API Key** 与连接测试
- **本地大模型一键部署**：没有 LM Studio 也能用 AI 讲解。引擎随安装包附带，只需下载模型（魔搭源约 14 MB/s）；三档可选（0.6B / 1.7B / 1.5B）。**左下角状态条点开就是启停面板**，会按当前用的是本机服务还是在线 API 分开显示状态与措辞
- **示例词库**：首次启动自动载入 20 个高频核心词（含音标、释义、变形、例句、记忆法），开箱即用
- **数据导入导出**：一键备份为 JSON，支持跨设备迁移
- **系统托盘**：打开主界面 / 显示侧边栏 / 开始复习 / 退出
- **浏览器 Mock 模式**：前端可脱离 Tauri 单独调试
- **词典源自测**：配置面板内置「测试连接」，逐源定位问题
- **快捷键**：`Ctrl+1~9` 切换页面，`A~D`/`1~4` 选答，`Esc` 关弹层

## 快速开始

### 1. 安装

下载 `WordWise-Setup-0.41.0.exe` 运行即可（安装向导支持中英文）。

若从源码构建，见 [构建与打包](#构建与打包)。

### 2. 直接开始背

首次启动会自动载入 **20 个示例单词**，点「开始背诵」就能用。

要导入自己的词库：**词库 → 批量导入**，粘贴单词列表（每行一个），
勾选「导入后立即联网补全释义」即可。

### 3. 配置 AI 讲解（可选但推荐）

AI 讲解需要一个**大模型服务**。三种办法任选其一，效果完全一样
（都走 OpenAI 兼容接口，程序分不出区别）。在**设置 → AI 服务**里选「服务来源」即可一键切换。

**办法一：用程序自带的一键部署（推荐，什么都不用装）**

推理引擎已随安装包附带，只要下个模型就行：

1. 点窗口**左下角的状态条**（写着「AI 服务」的那块）展开面板
2. 按钮会按「还缺什么」自动变：
   - 没装引擎 → **去安装引擎**（随包已有，瞬时完成）
   - 有引擎没模型 → **去下载模型**（走魔搭源，0.6B 约 400MB / 1.7B 约 1.1GB）
   - 都齐了 → **启动**；正在跑 → **停止（释放内存）**
3. 嫌每次手点麻烦，打开面板底部的**「启动时自动拉起」**，下次开程序就自动起好

服务只监听 `127.0.0.1`，不对外网开放；**退出 WordWise 会自动停止**，不会留孤儿进程。

**办法二：连接你已有的 LM Studio**

不用在终端敲任何命令，也不用配环境变量，只要两步：

1. 打开 LM Studio → **Chat** 标签 → 加载一个模型 → 切到 **Developer** 标签 →
   点 **Start Server**（默认就是 `http://127.0.0.1:1234`）
2. 回到 WordWise → **设置 → AI 服务** →「服务来源」选 **本机 LM Studio** →
   点「**测试连接**」。显示「已连接，共 N 个模型可用」就成了

`127.0.0.1:1234` 本来就是出厂默认地址，所以如果你从没改过设置，
装好 LM Studio 点完 Start Server 就能直接用，连设置都不用进。

> 同时配了一键部署和 LM Studio 也没关系：一键部署启动期间会用自带的服务，
> 停止后自动把地址**还回 `1234`**，不会互相打架。

**办法三：用在线 API（DeepSeek / 通义千问 / Kimi / 智谱 / OpenAI …）**

不想在本机跑模型，或者机器带不动，可以直接接在线的 OpenAI 兼容服务。
**设置 → AI 服务 → 服务来源**里已经内置了这几家的地址和推荐模型：

| 服务 | 地址 | 是否需要代理 |
|---|---|---|
| **DeepSeek** | `https://api.deepseek.com/v1` | 国内直连可用 |
| 阿里云通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 国内直连可用 |
| 月之暗面 Kimi | `https://api.moonshot.cn/v1` | 国内直连可用 |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | 国内直连可用 |
| 硅基流动 | `https://api.siliconflow.cn/v1` | 国内直连可用 |
| OpenRouter | `https://openrouter.ai/api/v1` | 一般需要 |
| OpenAI | `https://api.openai.com/v1` | 一般需要 |

用法：选好来源 → 点「**申请 API Key**」去对应官网拿一把 → 粘到 **API Key** 框里 →
点「**测试连接**」。任何 OpenAI 兼容的服务都能用，选「自定义」手动填地址即可。

- **需要代理的**（OpenAI / OpenRouter）：先到 **设置 → 网络与代理** 打开代理并填好地址，
  否则请求发不出去。程序默认是直连的。
- **Key 的存放**：只保存在本机数据库里（跟学习数据一起，**明文未加密**），
  只发给你填的那个服务，不会上传到别处。公用电脑上建议用完清空。
- **切换成本很低**：从在线切回本机模型（或反过来）随时都可以，改完点保存即可。

> 三种都没配时，在线查词完全可用，只是没有 AI 讲解和离线兜底。

### 4. 唤出侧边栏

点左下角「打开侧边栏」，或**左键单击托盘图标**即可显示/隐藏。

关闭主窗口不会退出程序，而是退到托盘并显示侧边栏 —— 方便随时查词。

## 功能详解

### 界面随词库（教材）语言自动适配

在背诵页选定一本词库后，整套界面文案会跟着这本词库的语言变：

| 词库语言 | 模式按钮 | 题面提示 |
|---|---|---|
| 英语（四级/考研…） | 看英选中 / 看中选英 | 请选择正确的英文单词 |
| 日语（JLPT N1–N5） | **看日选中** / 看中选日 | 请选择正确的日语单词 |
| 中文 | 看词选义（「看中选中」被下线） | 请选择正确的中文释义 |

同时有一个**释义语言**选择（中文释义 / 原文释义 / 不限）：

- 背外语教材时默认用**中文释义**，即使词典源先返回的是英文解释，也会优先挑出中文那条；
- 想练英英释义时切到「原文释义」，题面就改用词典给出的原文；
- 选择按词库语言分别记住，下次打开同一本词库沿用上次的设置。

### 朗读与发音

- 点音标旁的小喇叭、详情卡右上角的 🔊、翻译页与词级译文的「朗读」，
  走的是**系统内置语音**：离线可用、点下去立即出声，不联网、不弹窗。
- 选「自动」时优先挑神经网络音色（名字里带 Natural / Online 的系统语音），
  其次才是老式 SAPI 音色。
- 设置页「朗读与发音」里可以指定音色、调语速并试听；按语言分别记住。
- 读不到系统语音时（没装语音包）会**如实提示**，不会给一个永远空的下拉。

### 查词判定：只要有一个词典有结果就算成功

判定「查询成功 / 失败」时，**本地大模型是否开启不参与判断**。

链路是四层：本地词库 → 词典缓存 → 在线词典聚合 → 本地大模型兜底。
前两层或第三层任何一个拿到内容，就返回成功；第四层（AI）只是「前面都没结果时
的最后一根稻草」，它没启用、超时、返回空，都只会在结果上方留一条提示条：

> 本地大模型未启用，本次未使用 AI 兜底。

而**不是**把整条查询判成「查询失败」。只有当四层全都没结果时，才会显示失败，
并且文案会说明到底是哪种情况（没启用源 / 有响应但没解析出释义 / 全部超时）。

### 查词双策略：匹配式 + 启发式

词典源的返回结构五花八门，还经常改版。只靠字段映射精确取值，一旦上游改了
字段名，这个源就「连得上却查不出词」。所以每个源都走三级阶梯：

| 层级 | 依据 | 说明 |
|---|---|---|
| ① 匹配式 | 源配置里的 `mapping` | 字段名、层级完全对上，最准确，优先 |
| ② 启发式 | **内容长什么样** | 不看字段名看内容：音标长得像 `/.../`，释义挂在 `def`/`meaning`/`translation` 一类键下，例句是较长的自然语句 |
| ③ 纯文本 | 响应体不是 JSON | 源直接返回 HTML 页面时，剥掉标签与脚本后按行抽取 |

启发式/纯文本兜底出来的词条会被标记为**降级**：数据来源那一行会注明
「启发式解析」，并且**不写入缓存**（靠猜的结果不该被固定一周）。
纯文本兜底还额外要求整页必须出现查询词，并过滤掉导航、版权等样板文字，
避免把「Privacy Policy」当成某个词的释义。

### AI 讲解存档（讲解也是一种词库资料）

AI 讲解会**自动存档**，而且它本身就是一份可检索的词条资料：

- 讲解生成时后端顺手落库（表 `explain_store`，主键是「词 + 语言 + 讲解语言」，
  所以同一个词可以同时留中文讲解和英文讲解，互不覆盖）；
- **第二次点开同一个词直接读存档**，不再调模型 —— 本地小模型动辄十几秒，
  存档就是为了这个「秒回」；想刷新内容，提示条上有「重新讲解」；
- 存档顶部有一条「**并入词库**」：把讲解正文交给模型整理成结构化词条
  （`llm::entry_from_explain`，只搬运不发挥），写进 `words` 表并进入复习队列 ——
  讲解从「一段聊天文字」变成「一个可背的词条」；
- 词库页的搜索框**同时搜讲解正文**，讲过的词即使还没并入词库也能搜到
  （结果区会单独列出「AI 讲解存档」分区）；
- 设置 → 数据库页有「清理讲解存档」，默认保留已并入词库的那些。

### 整句查询（句子也能查）

在查词框里输入一整句（而不是一个词）时：

- 词典本来就不可能收录整句，所以程序会**自动改走整句翻译**，不再直接甩「查询失败」；
- 原文按词切开，**每个词都可以点**，点了就查那个词；
- 支持**栈式历史**：顶部「← 返回」（快捷键 `Alt + ←`）可以一路退回刚才查过的词，
  和浏览器后退的语义一致 —— 后退之后点新词会截断后面的分支。

### 双向背诵

点「看英选中」或「看中选英」切换模式。

- **看英选中**：显示英文单词 + 音标，四选一选中文释义
- **看中选英**：显示中文释义，四选一选英文单词

干扰项从当前语言词库中随机抽取，因此词库越大，题目质量越好。

答完即时反馈：答对显示绿色对勾；答错标红并显示正确答案，
同时提示「该词已加入强化记忆」。

### 记忆调度（需求 4）

WordWise 使用 **SM-2 改良算法**，核心是两条：

**① 记忆周期表**（可在设置中查看可视化）

```
第1次    第2次    第3次    第4次    第5次    第6次    第7次    第8次
 1天   →  2天   →  4天   →  7天   →  15天  →  30天  →  90天  → 180天
```

连续答对就沿表前进一格；答错则回到起点，并按 `lapse` 处理（半天后重现）。

**② 难度系数 EF（Ease Factor）**

- 初始 2.5，范围 [1.3, 3.2]
- 答「很简单」+0.1，答「有点难」-0.1，答错 -0.2
- 实际间隔 = 周期表基础值 × (EF / 2.5)

所以同一个词对「记得牢的人」和「总记不住的人」会走出不同的复习节奏。

**出题顺序**：

1. 强化记忆词（常错词）优先
2. 已逾期的词，逾期越久越优先
3. 数量不够时补「熟练度最低」的词
4. 还不够则引入词库中未学过的新词

**记忆强度**用指数遗忘曲线计算：`R = e^(-t/S)`，其中 S 为稳定性
（间隔 × 难度系数）。详情卡底部会显示这个值。

### 常错词强化（需求 5）

满足以下条件自动标记为「强化记忆」：

- 作答次数 ≥ 3
- 错误率 ≥ 50%
- 尚未掌握

强化词的复习间隔会被压缩到最多 1 天，并在出题队列中**排最前面**。

答错时（可在设置中关闭）自动弹出**完整详情卡**，含 5 个标签页：

| 标签页 | 内容 |
|---|---|
| 释义 | 分义项列出词性 + 中文释义 + 例句译文 |
| 变形 | 过去式 / 复数 / 比较级等，卡片式展示 |
| 例句 | 汇总所有义项下的例句 |
| 相关词 | 同义词 / 近义词，点击可直接跳转查询 |
| AI 讲解 | 本地大模型逐字流式讲解 |

卡片底部显示该词的学习状态：熟练度、正确率、下次复习时间。

### 联网查词（需求 2）

查询链路的优先级：

```
本地词库  →  词典缓存（7天）  →  在线多源聚合  →  本地大模型兜底
```

**在线多源聚合**：按优先级依次请求，一旦拿到「释义 + 音标 + 例句」就提前返回；
否则把各源结果**合并**（一个源给释义，另一个补变形和例句）。

内置 4 个源：

| 源 | 提供 | 需要 Key |
|---|---|---|
| Free Dictionary (dictionaryapi.dev) | 英英释义、音标、变形、同义词、例句 | 否 |
| Wiktionary | 多语言释义与例句 | 否 |
| 有道词典（公开建议接口） | 中文释义、词性 | 否 |
| LibreTranslate | 纯翻译（默认关闭） | 视实例 |

**输入联想**同时请求有道与必应两个建议接口，谁先返回谁上榜。

**维基百科知识**：查词时可附带该词的百科摘要（`cmd_search` 接口，前端已接好）。

### 小语种扩展（需求 6）

这是设计上最花心思的部分：**词典源 = 配置，不是代码**。

每个源由三部分组成：

```jsonc
{
  "id": "custom-1",
  "name": "我的法语词典",
  "enabled": true,
  "langs": ["fr"],                                    // 支持哪些语言
  "url_template": "https://api.x.com/dict?q={word}",  // {word} {lang} {key}
  "method": "GET",
  "api_key": "",
  "mapping": {                                        // JSON 字段路径映射
    "word": "result.headword",
    "phonetic_uk": "result.pronunciation.ipa",
    "senses": "result.entries",
    "sense_pos": "category",
    "sense_def": "meaningZh",
    "sense_examples": "samples[*]",
    "example_text": "fr",
    "example_translation": "zh"
  }
}
```

路径语法支持 `a.b.c`（逐层）、`a[0].b`（下标）、`a[*].b`（遍历收集）、`$`（根）。

因此**新增一门语言 = 加一条配置**。内置源（`dict/builtin.rs`）本身就用
同一套机制实现，是现成的模板。

完整指南见 **[docs/DICT_SOURCES.md](docs/DICT_SOURCES.md)**。

### 侧边栏（需求 7）

- 独立 Tauri 窗口，`always_on_top`，`decorations: false`，`skip_taskbar: true`
- 关闭时拦截 `CloseRequested` 改为 `hide()`，保证常驻
- 首次显示自动贴屏幕右侧垂直居中
- 打开时若词库非空，自动出一道快测题
- 主窗口关闭时自动显示侧边栏，服务不中断

### 数据与模型的存放位置

早期版本把数据**无条件**放 `%APPDATA%\WordWise`（C 盘）。后果是：用户把软件装到
D 盘，模型（单档 400MB~1.1GB）却还是往 C 盘写，而设置页里**没有任何入口能改**。

现在按六级规则解析（`state::resolve_data_dir_with`），优先级从高到低：

| # | 条件 | 结果 | 为什么 |
|---|---|---|---|
| ① | 设了 `WORDWISE_DATA_DIR` | 用它 | 脚本 / 高级用户显式指定，最高优先 |
| ② | exe 同级有 `portable.txt` | 文件里的路径；空文件 = `exe\data` | 便携模式：自包含，拷走即走 |
| ③ | exe 同级有 `location.txt` | 它指向的目录 | 用户在设置页换过目录 |
| ④ | `%APPDATA%\WordWise\wordwise.db` 已存在 | 就用它 | **老用户护城河**，见下 |
| ⑤ | `exe\data` 可写 | 用它 | **新装默认**：装到哪，数据就落哪 |
| ⑥ | 以上都不行 | `%APPDATA%\WordWise` | 兜底（exe 目录只读时） |

> ④ 必须排在 ⑤ 前面。否则老用户升级后数据目录会从 `%APPDATA%` 变成
> `<exe>\data`，新目录里没有 `wordwise.db`，应用会当成新装 ——
> 词库、进度、错词本看起来「凭空消失」。这条比「默认不写 C 盘」重要得多。

**模型目录可以单独换**（`localllm::models_dir`，三级：`WORDWISE_MODELS_DIR`
→ 数据目录里的 `models_dir.txt` → `<数据目录>\models`）。因为模型是唯一可能上 GB
的东西，用户的 C 盘往往够装程序、不够放模型，而数据目录本身他未必想动。

「设置 → 数据与模型的存放位置」里能看到：数据目录 / 模型目录 / 推理引擎各在哪、
各占多少、引擎是随包带的还是要联网下载、三档模型缺哪档、**每个盘还剩多少空间**，
并且可以把数据目录或模型目录换到别的盘（可选把现有文件一起搬过去）。

几条刻意的设计：

- **迁移不删源文件**。数据库走 `VACUUM INTO` 取一致性快照（直接拷 `.db` 可能拿到
  写一半的状态，或漏掉还在 WAL 里的已提交数据），其余文件递归复制且**不覆盖同名文件**。
- **拒绝嵌套**。新目录不能是旧目录的子目录或上级目录 —— 不拦的话迁移会自己复制自己，
  往正在遍历的树里写新文件，轻则无限膨胀，重则把盘写满。
- **恢复默认用不着删文件**：往指针文件里写 `default` 即可（本机的安全策略也会把
  删除动作 fail-closed 拦下来，写入是更可靠的做法）。
- **失败归因分开**：模型目录改完立刻生效（每次用的时候现读指针），数据目录必须重启
  才能换库，所以只有后者会提示重启并给一个「立即重启」按钮。
- **只读盘检测**：判「目录存在」不够，会真写一个探针文件再删掉 ——
  否则会在第一次下载模型时才抛出一个很晚、很难懂的错误。

### 选择「数据跟着软件走」的代价

数据放在 `exe\data` 时，删掉软件目录会**连词库一起删掉**。界面上会明确写出这一条，
安装程序的卸载流程也会就 `{app}\data` 单独询问一次。要长期保存，可以：

- 设置页里把数据目录换到别处（如 `D:\WordWiseData`），或
- 在「设置 → 数据库」里点一次备份（一致性快照），或
- 直接用便携版并整个文件夹保管好。

## 技术架构

### 技术选型

| 层 | 技术 | 理由 |
|---|---|---|
| 界面 | 原生 HTML/CSS/JS | 零构建步骤，无 node_modules，改完即生效 |
| 外壳 | Tauri v2 | 复用系统 WebView2，安装包小（~8 MB） |
| 后端 | Rust 1.77+ | 性能与内存安全，单二进制分发 |
| 存储 | SQLite (rusqlite bundled) | 无需外部依赖，单文件，随包分发 |
| 网络 | reqwest + rustls | 不依赖系统 schannel，规避证书吊销列表离线问题 |
| 打包 | Inno Setup 7 | 中文安装向导、自定义任务、卸载保留数据 |

### 分层设计

```
┌─────────────────────────────────────────────────┐
│  前端  src/                                      │
│  app.js(路由) study.js(背诵) lookup.js(查词+AI)  │
│  library.js  settings.js  sidebar.js  ui.js      │
│                      ↓ api.js (invoke/listen)    │
├─────────────────────────────────────────────────┤
│  命令层  commands/mod.rs  （40+ 个 #[tauri::command]）│
├─────────────────────────────────────────────────┤
│  业务层                                          │
│   srs/     记忆调度引擎 (SM-2 + 遗忘曲线)         │
│   dict/    多源聚合 + JSON路径映射 + 归一化        │
│   llm/     LM Studio 客户端 (含 SSE 流式)         │
│   search/  联想 + 维基知识                        │
├─────────────────────────────────────────────────┤
│  基础层                                          │
│   db/ (SQLite)   net/ (HTTP)   state/ (共享状态)  │
│   timeutil/ (系统时间)   models/ (数据模型)        │
└─────────────────────────────────────────────────┘
```

### 数据库表

| 表 | 用途 |
|---|---|
| `words` | 词库，存归一化后的 `WordEntry` JSON |
| `study_state` | 每词的学习状态（EF、间隔、到期时间、对错次数、熟练度） |
| `review_log` | 每次作答的日志（用于统计与遗忘曲线校准） |
| `config` | 应用配置（JSON） |
| `dict_sources` | 自定义词典源 |
| `dict_cache` | 词条缓存（避免重复联网） |
| `search_log` | 搜索历史 |
| `explain_store` | AI 讲解存档（可搜索；可一键整理成词条并入词库） |

### 关键实现细节

- **时间**：所有时间戳统一走 `timeutil::now_ts()`（系统本地时钟），
  自然日边界按本地时区计算，符合用户对「今天到期」的直觉。
- **并发**：查词时多个 HTTP 请求并行（`tokio::join!` / `buffer_unordered`）；
  数据库用 `parking_lot::Mutex` 包裹 `Connection`，短临界区，不跨 await 持锁。
- **流式**：LM Studio 的 SSE 响应逐行解析 `data:` 负载，
  通过 Tauri 事件 `explain://delta` 推给前端，实现打字机效果。
- **容错**：模型输出的 JSON 会自动剥离 ```json 代码块包裹；
  义项释义为数组时会用「；」拼接；推理模型的 `reasoning_content` 也会被接收。

## 构建与打包

### 环境要求

Rust 1.77+ · MSVC 2019/2022/2026 · Windows SDK · WebView2（Win10 1803+ 内置）

### 构建

```bash
# 开发运行
cd src-tauri && cargo run

# 发布构建
cd src-tauri && cargo build --release
# 产物：src-tauri/target/release/wordwise.exe
```

### 打包安装程序

```bash
# 一键（PowerShell）
.\build.ps1

# 交互式菜单（双击运行即可）
.\构建.ps1

# 或直接用 Inno Setup 编译（ISCC.exe 不在 PATH，必须写完整路径）
"G:\Programming\07-utils\Inno Setup 7\ISCC.exe" installer\wordwise.iss
# 产物：installer\output\WordWise-Setup-0.41.0.exe
```

> ISCC.exe 未加入系统 PATH。装在其他位置时：
> `.\build.ps1 -IsccPath "<你的路径>\ISCC.exe"`，或改 `build.ps1` 的 `$DefaultIscc`。

安装程序特性：中英文双语向导 · 桌面/快速启动图标 · 开机自启（侧边栏）·
安装后引导配置本地模型 · **卸载时可选保留学习数据**（`{app}\data` 与老用户的
`%APPDATA%\WordWise` 两处都会问）。

**默认安装目录优先选非 C 盘**：向导初始化时会依次试 `D:\` `E:\` `F:\`，
第一个「能建目录、能写文件」的会被设成默认值（目录名 `WordWise`）；
一个都不行就退回原来的 `%localappdata%\Programs`，不会因此装不上。
这样装到数据盘之后，词库和模型也跟着落在那儿，不写系统盘。
目录仍可手工改（向导里有那一页）。

### 便携版（免安装）

前端资源已内嵌进 exe，`wordwise.exe` 是**单文件绿色版**，拷到任何地方双击即可运行，
不写注册表、不往系统目录拷文件。

```
dist\wordwise.exe                                  便携版目录（自带 portable.txt）
installer\output\WordWise-0.41.0-portable.zip              便携包，不含模型（小）
installer\output\WordWise-0.41.0-portable-with-models.zip  便携包，含已下载的模型（大）
```

运行一次 `.\build.ps1` 会同时产出**两个便携包**和**安装程序**。
含模型那份是可选的（模型动辄 1GB+）：

```bash
.\build.ps1 -ModelsDir "D:\WordWise\data\models"   # 指定模型来源
.\build.ps1 -SkipModelsZip                         # 只要小的那份
```

本机没有已下载的 `.gguf` 时会自动跳过「含模型」那份，并提示候选目录。

- 系统要求：Windows 10/11（x64）+ WebView2 运行时（多数系统已自带）
- **便携版的数据在 exe 同级的 `data\` 里**（靠随包的空文件 `portable.txt` 实现），
  所以整个文件夹拷到 U 盘就能带着走；代价是**删掉文件夹会连词库一起删**
- 想换成「数据不在程序目录里」，删掉 `portable.txt` 即可（或改用下面的
  环境变量 / 设置页）

### 上传到 GitHub

```bash
python scripts/upload_github.py --public
```

脚本会按以下顺序自动寻找 token：

1. 环境变量 `GITHUB_TOKEN` / `GH_TOKEN`
2. **hermes 配置**：`%LOCALAPPDATA%\hermes\.env` 中的 `GITHUB_TOKEN=`
3. **hermes 凭据池**：`%LOCALAPPDATA%\hermes\auth.json` 的 `credential_pool`
4. `~/.config/wordwise/github_token`

然后校验身份 → 创建仓库 → `git init` 并提交 → 推送，全程无需手工操作。

## 常见问题

**Q：提示「本地模型未连接」怎么办？**  
A：在线查词不受影响。需要 AI 讲解时，按[快速开始第 3 步](#3-配置-ai-讲解可选但推荐)启动本地模型服务。

**Q：还要像以前那样手动去终端敲 `lms server start` 吗？**  
A：不用了。点左下角状态条 →「启动」即可，引擎随包附带、不用自己装。
只有选「办法二：自己装 LM Studio」时才需要 Start Server，而且那也是一次性的。

**Q：本地服务怎么关？会不会一直占着内存？**  
A：面板上点「停止（释放内存）」就关了；直接退出 WordWise 也会自动停，
不会留孤儿进程。想让它每次开程序自动起，打开面板里的「启动时自动拉起」。

**Q：我已经装了 LM Studio，怎么连上？**  
A：LM Studio 里加载模型 → Developer 标签点 Start Server → 回 WordWise 点
「设置 → AI 服务 → 测试连接」。地址 `127.0.0.1:1234` 本来就是默认值，
没改过设置的话连地址都不用填。

**Q：不想在本机跑模型，能用网上的 API 吗？**  
A：能。设置 → AI 服务 → 服务来源里选一家（DeepSeek、通义千问、Kimi、智谱 GLM 等），
点「申请 API Key」拿到 Key 粘进去，再点「测试连接」即可。任何 OpenAI 兼容的服务都行。
OpenAI / OpenRouter 这类境外服务要先在「设置 → 网络与代理」里打开代理。

**Q：在线 API 的 Key 存在哪？安全吗？**  
A：存在本机数据库里（跟学习数据同一个文件，明文未加密），只会发给你自己填的那个服务。
程序不做任何其它上传。公用电脑上建议用完清空 Key。

**Q：查词一直失败？**  
A：进入「设置 → 词典与翻译源」，逐个点「测试」定位问题源。
**AI 没开不会导致查词失败** —— 只要有一个词典源返回结果就算成功（v0.40.0 起），
AI 兜底只是锦上添花。若是网络问题，注意本机代理设置（`HTTPS_PROXY`）。

**Q：我把软件装在 D 盘，模型怎么还是跑到 C 盘了？**  
A：v0.41.0 起不会了：数据默认跟着软件目录走（`<安装目录>\data`）。
如果是从老版本升级上来的，原本的数据仍在 `%APPDATA%\WordWise`（刻意不搬，
免得看起来像「词库丢了」）。想挪走：**设置 → 数据与模型的存放位置 →
模型文件那一行的「更换目录」**，只挪模型不用动数据目录，也不用重启。

**Q：便携版删掉文件夹，词库也没了？**  
A：便携版的数据就在 exe 同级的 `data\` 里（这就是「换个电脑接着背」的代价）。
删之前先到「设置 → 数据库」点一次备份，或者删掉目录里的 `portable.txt`
让数据换个地方放。

**Q：程序装在哪、数据在哪，我怎么一眼看清？**  
A：**设置 → 数据与模型的存放位置**：数据目录 / 模型目录 / 推理引擎三行，
各自标着「为什么是这个目录」，下面还有每个盘的剩余空间。

**Q：音标或变形不显示？**  
A：到「设置 → 记忆辅助内容」检查对应开关 —— 这是需求 3 的可选开关，
默认「相关词」是关闭的。

**Q：想加一门新语言？**  
A：见 [docs/DICT_SOURCES.md](docs/DICT_SOURCES.md)。
在「设置 → 词典与翻译源 → 新增源」里填 URL 模板和字段映射即可，无需改代码。

**Q：选了日语，翻译却只显示罗马音 / 显示成英语？**  
A：v0.35 起译文主体与读音已严格分离，读音只作附属标注单独一行；
语言码全链路统一。若仍异常，见 [docs/TRANSLATE.md](docs/TRANSLATE.md)
的「语言码的四个卡点」逐段对照。

**Q：翻译提示「触发频率限制」？**  
A：在线翻译接口限频很严。程序会自动冷却 20 秒并降级到本地大模型，
稍等即可自动恢复；重复点「重译」只会延长冷却。

**Q：学习数据在哪？重装会丢吗？**  
A：`%APPDATA%\WordWise\wordwise.db`。卸载时会询问是否删除；
选「否」则保留，重装后继续原有进度。也可用「导出备份」生成 JSON。

**Q：词库太小，题目干扰项不够？**  
A：干扰项从词库随机抽取，建议至少导入 30 个词。
可先点「载入示例词库」凑够数量。

**Q：能同时背多门语言吗？**  
A：可以。在「设置 → 学习语言」切换，不同语言的词库与学习进度互相独立
（数据库按 `(word, lang)` 联合主键区分）。
