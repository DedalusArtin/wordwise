## 二、需求 5 的真实前提：项目本来就是 SQLite

收到需求时先查了存储层，结论是**不需要改造**：

```
%APPDATA%\WordWise\wordwise.db      ← rusqlite + bundled（13 张表）
```

`state.rs:61` 一行就定死了路径。所以「改用 SQLite」这条真正缺的是**可见性**：
用户不知道文件在哪、多大、坏了怎么办。

因此做了三件事：

1. **看得见** —— `cmd_db_info` 返回路径、体积、WAL 体积、13 张表各自多少行（带中文表名）。
2. **管得住** —— `cmd_db_maintain` 三个动作：`vacuum`（回收空洞并回报前后体积）、
   `check`（`PRAGMA integrity_check`）、`backup`。
3. **验得了** —— 备份用 `VACUUM INTO` 而不是直接复制 `.db` 文件。直接复制可能
   拿到「写入到一半」的状态，`VACUUM INTO` 拿到的是一致性快照。

## 三、知识图谱：为什么不引 D3 / ECharts

前端是「`<script>` 顺序加载 + 全局作用域」，没有打包器。引第三方可视化库意味着
多一个 CDN 依赖，离线即失效。自研力导向布局只有一百多行（`graph.js` 的
`iterate()`），反而更可控。

三个关键取舍：

- **节点上限 150**。斥力是 O(n²)，300 个节点每帧 9 万次计算，低配机器会掉帧。
  后端另外按权重截断（全局边上限 240，聚焦视图 160）。
- **AI 发散的边画虚线**。词典里写明的关系是确定的，模型猜的是推测的。
  视觉上必须分开，否则用户会把模型编的词当真。
- **词库外的节点画空心**。点它是「去查词」而不是「看详情」——
  没有完整词条，详情卡打开会是空的。

点击语义也做了区分：**单击** = 以该词为中心重新展开（向后端要 1-2 跳子图，
而不是前端在已有数据里过滤，因为后端的边可能比当前这张图多得多）；
**双击** = 打开详情卡。两者用 260ms 延时错开，避免双击时触发两次展开。

## 四、演示模式：为什么必须「不入库」

演示数据的诱惑做法是往库里灌一批假词。一旦这么做：

- 用户的真实学习记录里混进假数据，永远清不干净；
- 「连续学习 9 天」这种指标会被污染，用户会以为自己真的学了。

所以做成**前端拦截 + 白名单**：

```js
// api.js
if (window.Demo && window.Demo.enabled && window.Demo.has(cmd)) {
  return window.Demo.for(cmd, args);
}
```

白名单里**只有读命令**（`cmd_stats`、`cmd_review_plan`、`cmd_due_words`、
`cmd_leech_query`、`cmd_leech_summary`、`cmd_graph_*`）。写命令
（`cmd_submit_answer`、`cmd_clear_leech`、`cmd_save_config`…）一律不拦，
所以演示模式下真去背单词，成绩照样进真实库。

冒烟测试专门守着这条边界：

```js
for (const w of ['cmd_submit_answer','cmd_clear_leech','cmd_save_config','cmd_graph_build']) {
  if (sandbox.Demo.has(w)) throw new Error('演示模式不该拦截写命令 ' + w);
}
```

另外开启后有一条常驻横幅，避免用户把示例当成自己的成绩。

## 五、错题导出：Markdown 与 CSV 各解决什么

- **Markdown**：给人看。带释义、例句、错因统计，可直接打印或贴进笔记。
- **CSV**：给机器看。丢进 Excel 做统计，或导入 Anki 做后续复习。

一个容易踩的坑：**CSV 必须带 UTF-8 BOM**（`\u{feff}`），否则 Excel 打开中文
是乱码。国内用户几乎都用 Excel，这一步不能省。

导出的筛选条件与列表当前筛选**完全一致**——所见即所得，不会出现「列表里
看到 5 个词，导出却是 12 个」。

## 六、错词筛选：错误率 ≠ 错误次数

筛选项给了三个：最少错次数、错误率、掌握度上限。

看起来冗余，实际不然。一个词错了 8 次但也对了 8 次（错误率 50%），
另一个词错了 3 次、对了 0 次（错误率 100%）。只按次数筛会漏掉后者，
而它恰恰最该优先背。所以两个维度都要有。

后端单测锁住了这个语义：

```rust
/// 错误率 ≥ 60% 只能命中 reluctant（3 错 0 对）；
/// abandon 虽然错了 8 次，但错误率只有 50%，不该出现
assert_eq!(words, vec!["reluctant"], "错误率筛选不能用错误次数代替");
```

排序字段走**白名单映射**而不是字符串拼接——它会被拼进 SQL，直接透传用户
参数就是注入入口。同样有单测守着（传 `wrong; DROP TABLE study_state` 应回退默认排序）。

## 七、复习计划：补一个「现在该背哪些」

「未来 14 天安排」回答的是「哪天有多少」，但真要动手时用户问的是
「**现在该背哪几个**」。所以新增 `cmd_due_words`，把逾期和今天到期的词
逐条列出来。

排序规则：逾期越久越靠前 → 其次按到期时间 → 最后强化词优先。
后端 `due_states` 原本是「先强化词、再按到期时间」，这对出题是对的，
但列表给人看时「逾期 5 天」排在「今天到期」后面会很怪，所以命令里重排了一次。

## 八、本地大模型一键部署：为什么改成随包

原本设计是「首次使用时联网下载引擎」。实测：

| 源 | 速度 | 33MB 引擎耗时 |
|---|---|---|
| modelscope.cn | 14.5 MB/s | — （模型走这条，1.1GB 约 80 秒） |
| huggingface.co | 不通 | — |
| gh-proxy.com | ~40 KB/s（且并发无效） | **14 分钟** |

14 分钟的等待没有任何产品能接受，所以改成**随安装包分发**：
`vendor/llama/`（24 个文件，89.5 MB）打进安装程序与便携版。
运行时优先用随包的，缺失才回退下载（`find_engine()` 的顺序）。

模型仍然走魔搭（14.5 MB/s），且只下用户选的那一档。
