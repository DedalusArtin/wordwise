WordWise 是一款 Windows 桌面背单词软件：左边是干净的词条，右边是本地大模型逐字写出的讲解，答错的词自己钻进错词本、按遗忘曲线准时回到你眼前。前端纯原生 HTML/CSS/JS（无 node_modules），后端 Rust + Tauri 2，离线可用。

本版是自 **v0.41.0** 以来的第一个正式发布。

## 本版重点

### 1. 背诵：进站即背，答错的词必须连对才放过

- **今日复习统一入口**：主页直接给出「今日待复习 N」，这个 N 已经把**到期**与**常错（leech）**合并算好 —— 不用自己两个数加起来。已经在背的时候点它只滚动定位，不会把当前这一轮打断重开。
- **错词攻坚按「连对」出队**：以前用累计答对次数，`对/错/对/错` 这种摇摆也会慢慢把词放走，可它其实根本没记住。现在改为**连续答对**才出队，中途错一次立刻重新计数 —— 判据恰好等价于「连续几次都想起来了」。不在攻坚队列里的词答对了不提示，避免刷屏。
- **全键盘流**：答完不用干等。回车立刻进下一题，空格在**任意题型**下都是发音（原来是绑在 listen_spell 上的死分支，从来没执行过）。手动抢先与自动推进互斥，不会跳两题。答题计数区新增「连对 N」实时显示。

### 2. 查词结果改成分块卡片（参照有道词典）

大词头 + 音标成对紧随其下 + 来源标签，再往下是标签栏，**一次只呈现一块**：释义 / 变形 / 记忆法 / 相关词。长词条不再被撑成一条读不完的竖条。

- 中文释义与英英释义**分组呈现**（母语在前、原文在后），中间用虚线分隔，不再「中文、英文、中文…」来回跳
- 详情卡的「释义」面板**复用同一套渲染** —— 以前它自己手搓了一遍义项 DOM，结果是「结果页分组、详情卡混排」。现在两处同源，改一处两边一起变
- 对应词卡片（「乌鸦」→ crow / rook / raven）仍是**纵向堆叠**：词头已经画在卡片标题上了，再套一排标签只是让用户多点一次

### 3. 安装包：自动检测旧版本并升级，组件可联网下载

- **升级检测**：安装时按 DisplayName 全量扫描卸载键，只要名字里含 WordWise 就识别为「已安装」，自动走升级流程并保留词库与背诵进度。
  > 为什么不能只认自己的 AppId：历史上该软件还被 Tauri NSIS / MSI 产出过，AppId 各不相同，只认一个会漏掉真装着的那一版。
- **在线安装**：安装过程中可选「需要联网下载的模块与模型」（llama 引擎、piper 语音引擎、语音包）。勾了才下载，不勾就装一个纯离线骨架，装完随时补。

## Android 版的能力差异（重要）

APK 版本**会降低模型能力**，这不是参数没调好，是平台限制：

| 能力 | Windows | Android | 原因 |
| --- | --- | --- | --- |
| 本地大模型讲解（llama.cpp） | ✅ | ❌ | Android 从 API 29 起禁止 App 执行自己数据目录里的外部二进制（W^X），而 `llama-server` 是 `std::process::Command` 拉起的外部进程 |
| 本地神经语音（piper） | ✅ | ❌ | 同上，piper 也是外部进程 |
| 系统 TTS 朗读 | ✅ | ✅ | 走平台自带 TTS，不受影响 |
| 在线词典查词 / 在线 AI | ✅ | ✅ | 纯网络请求 |
| 词库 / 背诵 / 错词本 / 复习计划 | ✅ | ✅ | 纯本地数据 |
| 多窗口侧边栏 | ✅ | ❌ | 移动端没有常驻窗口的概念 |
| 系统托盘 | ✅ | ❌ | 同上 |
| 便携模式（数据跟随 exe） | ✅ | ❌ | 移动端数据目录由系统分配（应用私有目录） |

界面上，不支持的入口会**明确给出原因**而不是静默失败 —— 静默 `Ok(())` 更糟，界面会以为功能已经生效了。

### 签名（升级安装的前提）

APK 用 `installer/android/wordwise-release.jks` 正式自签名（该密钥与口令**不入库**，见 `.gitignore` 里的说明）：

| 项 | 值 |
| --- | --- |
| 证书主体 | `CN=WordWise, OU=WordWise Android, O=DedalusArtin, C=CN` |
| 别名 | `wordwise` |
| 算法 | RSA 2048 / SHA256withRSA |
| 有效期 | 至 2054-02-21 |
| 证书 SHA-256 | `77:92:63:BE:8B:1D:56:73:78:8A:3A:3B:F2:36:33:52:72:90:6B:29:F7:EA:1D:87:D5:A3:29:17:0B:91:40:1F` |

> **这个密钥必须长期妥善保管（至少两处备份）。** 换密钥后，老版本会被系统判为「签名不一致」而拒绝覆盖安装，用户只能先卸载 —— 而卸载会连词库和背诵进度一起删掉。

签名方案实测：`apksigner verify` 通过 **v2 + v3**（`minSdk 24` 起 v2 即足够，v1 不再需要）。产出不带 `-unsigned` 后缀，可安装。

### 构建侧两个必须记住的坑

1. **`src/lib.rs` 的 `#[cfg_attr(mobile, tauri::mobile_entry_point)]` 不能少。**
   它展开出 `Java_app_tauri_plugin_PluginManager_handlePluginResponse` 等 JNI 胶水符号。漏掉时的表现极具迷惑性：编译**完全通过**、APK **正常产出**，但因为没有导出符号引用 `run()`，链接期 `--gc-sections` 会把整个 tauri 运行时剥光 —— 实测产物只有 **308 KB**、`llvm-nm -D` 输出 **0 行**（正常是 10.4 MB / 24 个 `Java_` 符号），装到手机上启动即闪退。
2. **jniLibs 不再依赖符号链接。** tauri-cli 走 cargo-mobile2，后者是在 `app/src/main/jniLibs/<abi>/` 下建一个指向 cargo 产物的**符号链接**。Windows 建符号链接要开发者模式/管理员权限；更阴的是受限环境会把它**静默降级成 0 字节普通文件**（`ln` 返回 0，日志还照打 "symlinking lib ..."），构建一路绿灯、包里却是空 `.so`。现在 `buildSrc/.../BuildTask.kt` 在 rust 构建后做确定性拷贝，任何权限环境下行为一致。

### 怎么重新出这三个包

```bash
# Windows 安装版 + 便携版（Inno Setup 7 不在 PATH，build.ps1 里用绝对路径调用）
pwsh -File build.ps1

# Android APK（arm64）
source scripts/android-env.sh          # RUSTUP_HOME / CARGO_HOME / ANDROID_HOME / NDK_HOME / JAVA_HOME
cd src-tauri && cargo tauri android build --target aarch64 --apk
# 产物：src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release.apk
```

- **APK 签名密钥**：`installer/android/wordwise-release.jks` + 同目录 `keystore.properties`（两者都已被 `.gitignore` 排除）。
  这两个文件**不在 git 里**，所以换机器时要手动拷过去；丢了就再也签不出可覆盖升级的包。Gradle 找不到它们时**不会报错**，只是产出未签名的 `-unsigned.apk`（装不上），务必留意文件名里有没有 `-unsigned`。
- `build.ps1` 会把 `CARGO_TARGET_DIR` 固定成 `src-tauri\target`，而外部 shell 里它可能是别的值（本次实测是 `D:\Projects\.cargo-target`）。两者都能用，`BuildTask.kt` 关于产物位置的判断同时认这两个。
