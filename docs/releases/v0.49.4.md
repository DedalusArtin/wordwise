# WordWise v0.49.4 —— 变形栏终于有「算法」了：saw → see、词性决定变形、不再出现 cee

> 承接 v0.49.3。这一版的主线是**查词页变形栏的四个真错**，
> 顺带把 v0.49.0 落地的「查询历史」后端与「词条数据模型扩展」一并交付。
>
> 一句话概括根因：变形栏以前只有**渲染**，没有**算法** ——
> 它把词条里现成的 `inflections` 原样铺出来，自己一个变形都不会算。
> 于是「数据里没有的变形」一律消失，「数据里写错的」一律照抄。

## 一、你报的四个问题，逐个交代

| 现象 | 根因 | 本版做法 |
| --- | --- | --- |
| **「saw 是 see 的过去式，这个就没有」** | 变形栏不做反向查找，词条里没写 `saw` 就是没有 | 新增 `morph_en` 形态学模块 + `cmd_forms_of`：查 `saw` 先判定它是谁的变形，再把 `see` 的完整变形集补齐 |
| **名词显示「原形（现在时）」** | 原形标签是**写死的**一句话 | 标签按词性走：动词→`原形（现在时）`、名词→`原形（单数）`、形容词/副词→`原形（原级）` |
| **动词出现一个假的「复数 sees」** | 变形不做词性过滤，`see` 数据里的 `复数 sees` 被动词原样渲染 | 动词只收 `三单/现在分词/过去式/过去分词`；`复数` 只留给名词 |
| **「cee 什么鬼」** | 原形提取用的是「共享前几个字符」的启发式，而 `see/cee` 恰好满足 | 判定改为「首字母相同 **或** 已知不规则配对」；`cee` 两条都不满足，被挡掉 |

### 关键的一个认知：不规则变形会换掉词头

`see → saw`、`go → went`、`be → was`、`buy → bought` ——
这些**恰恰是最需要认出来的变形**，它们的共同点是**首字母都变了**。
所以任何「共享前导字符」的启发式，都只会把最该认出的那批词全部挡在门外。

正确判据是**穷举**：`see` 的不规则变形是 `saw/seen`，这是词表事实，不是拼写字面可以推出来的。
本版把它做成一张表。

## 二、新增 `src-tauri/src/morph_en.rs`（本版核心）

一个纯本地、零网络、零 IPC 等待的英语形态学模块。

| 内容 | 规模 |
| --- | --- |
| 不规则动词表（原形 / 过去式 / 过去分词） | **141 条** |
| 不规则复数表 | **28 条** |
| 单测 | **18 条** |

### 收词有一条硬规矩，并且由测试钉住

> **能靠规则拼写算出来的词，绝不收进不规则表。**

这不是洁癖。收进来会有两个后果：一是表越来越臃肿，二是**真正的死数据没人敢删**。
所以 `irregular_table_is_sane` 这条单测的断言是「每个词条至少有一个形式**偏离**规则拼写」，
而不是「过去式 ≠ 原形」（后者会把 `beat/beat/beaten`、`cost/cost/cost` 这类 AAA 型动词误判为冗余）。

这条测试当场抓出了 10 条我自己塞进去的死数据：
`burn` `dream` `learn` `lean` `light` `prove` `dive` `smell` `spell` `spill`
—— 它们的过去式都能由 `+ed` 规则推出，已全部移出。

### 反向查找返回**全部**候选，不猜

```rust
pub fn bases_of(form: &str) -> Vec<(String, String)>   // (原形, 变形类型)
```

`left` 既是 `leave` 的过去式，也是别的词的变形；`lent` 是 `lend` 的过去式；
`found` 既是 `find` 的过去式也是「建立」的原形。所以返回**所有**可能，
由 `cmd_forms_of` 再用「谁在库里」来投票，而不是在形态层擅作主张。

规则反推（`regular_bases`）覆盖 `-ies / -es / -ed / -ing / -s`，
并处理**双写辅音还原**（`planned → plan`）与**静默 e 还原**（`hoping → hope`）。

### 词性解析有个坑：`adv.` 里有个 `v`

按「首字母是不是 v」判动词会把 `adv.` 当成动词。
`Pos::parse` 的做法是**先按非字母切词，再整词匹配**，所以 `adv.` 只能命中 `adv`。

## 三、后端 `cmd_forms_of`：判定顺序是刻意的

```
① 词本身就在库里   → 它就是自己的原形（saw 作为名词「锯子」不该被 see 盖掉）
② 不规则表反向查   → 多个候选时，优先选「库里真有的那个」
③ 由词性决定生成哪些变形
```

第 ① 条看着反直觉，但是必要的：如果一律优先反查，`saw`（锯子）会被判成 `see` 的过去式，
用户查工具名词却拿到动词的全部时态。

前端 `src/js/lookup.js` 拿到结果后在词条上方渲染一行提示，
点「载入」会带着 `{ fromNav: true, silentHistory: true, keepScroll: true }` 重查原形 ——
**记进历史**和**滚动位置**这两个副作用都要关掉，否则「点一下看看原形」会污染历史列表。

配套的 `cmd_lookup` 新增了第 5 个参数 `record_history: Option<bool>`（默认 `true`），
就是为这条路径准备的。

### 一个只有真跑才会暴露的 bug：`sees` 渲染了三次

去重只维护了「已渲染集合」`seenForm`，而**本地兜底**那一步查的也是它。
于是 `复数 sees` 被动词栏过滤掉之后，`seenForm` 里并没有它，
兜底逻辑认为「没渲染过」就补了一条，于是同一个词出现三遍。

修法是维护**两个集合**：`seenForm`（渲染了什么）与 `allForms`（数据里出现过什么）。
兜底只看后者。

顺带说一句，这条最初连测试都写错了 —— 我数的是字符串 `sees` 的出现次数，
而一个渲染块里 `sees` 本身就出现 3 次（`data` 属性、显示文本等）。
改成数 `infl-item` 块数才是真正在数「渲染了几条」。

## 五、查询历史：后端落地

| 接口 | 说明 |
| --- | --- |
| `Db::recent_search_rows(limit)` | 按词去重，返回 `SearchLogRow { query, at, times }` |
| `Db::delete_search_history(query)` | 单条删除 |
| `Db::clear_search_history()` | 清空 |
| `cmd_recent_searches` / `cmd_delete_search_history` / `cmd_clear_search_history` | IPC 层 |

**顺手修掉一个「历史看起来像丢了」的老 bug**：

```sql
-- 改前
SELECT DISTINCT query FROM search_log ORDER BY at DESC
```

`DISTINCT` 之后每个词只剩一行，而 `at` 不在 `SELECT` 列表里 ——
SQLite 只会从这个词的**任意一行**里任取一个值参与排序（实测拿的是 rowid 最小的那条，
也就是这个词**最早**被查的时间）。后果极难察觉：「半年前查过、刚刚又查了一遍」的词
会沉到列表最底部，用户以为历史没记。

改成 `GROUP BY query` + `MAX(at)` 才是「按最近查询时间排序」的正确写法。

> 前端面板（输入框下方的历史列表）**本版不含**，见第七节第 2 条。

## 六、数据模型扩展 + 一个真的会丢数据的 bug

`WordEntry` 新增三栏，对应 AI 讲解「六栏」里的后三栏：

| 字段 | 结构 | 为什么不塞进旧字段 |
| --- | --- | --- |
| `exam_points: Vec<String>` | 考点（四六级 / 考研 / 雅思…） | 考点要能**从本地词库归属自动发现**，不该让模型猜 |
| `collocations: Vec<Collocation>` | 常见搭配（词组 + 用法说明） | `related` 只有一个词形，搭配少一半就不是搭配 |
| `confusables: Vec<Confusable>` | 易混辨析（易混词 + 区别说明） | 同上 |

`llm/mod.rs` 里三栏的解析一律**宽松优先**：本地小模型常常把本该是对象的地方吐成字符串，
严格取值会让整栏丢失，宽容处理至少保住一半信息。

### `merge_explain_fields` 会静默吞掉旧例句

原实现只有 `find_sense` **语义匹配成功**时才回收旧例句。
模型一旦改写释义措辞（这在本地小模型上是常态），匹配必然失败，
旧例句就被整片替换掉了 —— 不报错、不告警，只是数据没了。

补了两级兜底：

1. **位置兜底**：`merged.len() == old_senses.len()` 时按下标回收；
2. **孤儿回收**：释义条数变了，就把没被认领的旧例句（按 `norm(&e.text)` 去重）收进第一条释义。

这条是 `explain_fields::tests::core_meaning_replaced_when_fresh_usable`
从 `left:0 right:1` 的失败里抓出来的。

## 手动验证步骤

1. **saw → see**：查 `saw` → 词条上方应出现「saw 是 see 的过去式 · 载入 see 的词条」，
   点「载入」后应拿到 `see / sees / saw / seen / seeing` 的完整变形表，
   且**查询历史里不会多出一条 see**。
2. **不该认的别认**：查 `cee` → 不应出现任何「…的原形」提示。
3. **名词不再显示「现在时」**：查 `book` → 原形标签应为「原形（单数）」，
   变形只有 `复数 books`。
4. **动词不再有假复数**：查 `see` → 变形栏不得出现「复数」，且 `sees` 只出现**一次**。
5. **形容词/副词**：查 `big` → 原形标签「原形（原级）」，变形为 `bigger / biggest`。
6. **历史排序**：查一个很久以前查过的词 → 它应排到历史列表最前面（不是沉底）。
