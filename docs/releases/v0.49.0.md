## 本版三件事

| # | 问题 | 本版做法 |
| --- | --- | --- |
| 1 | **背单词时总混进日语**：英语词表里出现 `('en','嗚呼')` 这类记录 | 建**语种闸门**：入库前按书写系统判定，假名判日语、谚文判韩语、纯汉字判中文，只有拉丁字母才归英语。闸门挂在写库唯一汇聚点，10 条入库路径无一漏网 |

## 1. 语种闸门：日语是怎么混进来的，又为什么现在进不来

### 根因不是写错了一行，而是「入库侧从来就没有闸门」

`dict::detect_lang` 这套字符级语言判定此前只用在**查词**和**翻译**两处展示侧，
10 条入库路径（下载导入 / 文件导入 / 手动加词 / 批量导入 / AI 生成 / 讲解并入 /
后台增强 / 备份导入 / 示例词库 / 音标回写）**没有一条调用它**。
而界面（`index.html` 词条语言一节）却写着「程序按书写系统自动判断」，
用户据此信任、随手粘贴日语 —— 于是三种写法同时把日语词写成了 `en`：

| 路径 | 为什么漏 |
| --- | --- |
| `cmd_import_words` 批量导入 | 唯一过滤器 `is_plausible_word` 对假名一律放行（`char::is_alphabetic()` 对 `あ`/`嗚` 返回 true），语言一律取 `target_lang` |
| `cmd_add_word` 手动加词 | 完全信任前端传来的 `entry.lang`，一个字的校验都没有 |
| `parse_json` / `parse_csv`（带表头） | **绕过**了 `looks_like_word` 这道词形闸门，只判「词不为空」 |

### 修法：三层，主闸在写库唯一汇聚点

| 层 | 改动 | 位置 |
| --- | --- | --- |
| 唯一实现 | 新建 `src-tauri/src/lang.rs`：`script_of` / `lang_compatible` / `resolve_lang` / `detect_lang`，把此前散落 5 处的 Unicode 区间判断收成一份 | `lang.rs` |
| **主闸** | `Db::upsert_word_gated` / `Db::bulk_upsert_words_gated`：不自洽就不写库，并把被拦下的词与理由返回给界面 | `db/mod.rs` |
| 命令层 | `cmd_add_word` / `cmd_import_words` 先按字形决议语言（`resolve_lang`），导入报告新增 `filtered` 与 `filtered_samples`，如实告诉用户「拦下了几条、为什么」 | `commands/mod.rs`、`commands/books.rs` |

判定规则（从严到宽，单元测试逐条钉死）：

| 词形 | 允许的语言 | 说明 |
| --- | --- | --- |
| 假名（含「汉字+假名」） | 只有 `ja` | 头号拦截目标 |
| 谚文 | `ko` |  |
| 汉字（无假名） | `zh` 或 `ja` | 汉字词在这两个词库都成立，但在 `en` 表里一定是噪声 |
| 西里尔 / 希腊 / 泰 / 阿拉伯 / 希伯来 | 对应语言 |  |
| **拉丁字母** | 一律放行 | `café` / `naïve` / `piñata` 不能误杀；日语词库里的拉丁外来语（如 `April`）也不能误杀。英/法/德之间字形分不出来，那是 AI 自检的活 |

### 存量脏数据：只搬不删

新增 `purge_lang_mismatch`：**启动时自动跑一遍**，也可在设置页「词条质量 → 清理语种错标」
手动跑。它把 `('en','嗚呼')` 搬成 `('ja','嗚呼')`，`wordbook_words` 归属与
`study_state` 学习进度同步迁移，且**只在目标行确实存在时才删旧行** ——
用户的词一条都不会消失，进度也不会被清空。

设置页「词条质量 → 语种统计」可直读词库的语言构成，清理前后能对账。

## 2. AI 词条自检

### 校验什么

每个词条由本地大模型校四个维度：**拼写**（词目是否与其释义、变形自洽）、
**词性**（`pos` 是否合法且与释义匹配）、**中文释义**（是否准确、是否残留 `<` 等噪声）、
**例句**（英文例句是否真实且含该词、译文是否与原文对得上）。

### 流程：只判不改、改完复检

```
取词条 → 模型判定
           ├─ ok        → 标记 ok，记日志
           ├─ fixed     → 采纳修正 → 写回 → 再跑一轮（round+1）
           │                ├─ 复检通过 → 标记 fixed，记日志（含改前改后 JSON）
           │                └─ 复检不过 → 标记 rejected
           └─ rejected  → 标记 rejected（不真删）
```

- **模型把词目也改了就拒绝采纳**：自作主张把 A 词改成 B 词，等于用 B 的数据覆盖 A；
- **模型返回不可解析就按不合格处理**，并把原因写进日志 —— 绝不让模型的闲聊进词库；
- **剔除 = 标记，不真删**：`words.audit_state='rejected'`，出题队列（复习 / 新词 / 干扰项）
  据此跳过，随时可恢复；
- **没配本地大模型不算失败**：命令返回明确提示指路设置页，绝不阻塞导入。

### 可追溯日志

新建 `ai_audit_log` 表：批次号、词、语言、第几轮、判定、问题项、人话说明、
**改前/改后的完整 JSON**、用的模型、耗时。同一句话也送进运行日志，
诊断面板（`cmd_log_analysis`）能看见。设置页「词条质量」下方可直接查最近 50 条。

## 3. 迷你悬浮窗

托盘菜单「显示/隐藏迷你背词窗」呼出，默认贴屏幕右下角、置顶、无边框、不占任务栏。

| 能力 | 实现 |
| --- | --- |
| 单词 + 释义 + 发音 | 与主窗口同一套发音链路（本地 Piper → edge-tts → 系统语音三级回退） |
| 认识 / 不认识 | 直接映射 SRS 的 `good` / `wrong`；空格或回车 = 认识，Backspace = 不认识 |
| 复习间隔 | 提交后显示「下次复习 …」，取 `cmd_word_state` 的 `due_text` |
| 今日进度 | 底栏常显「今日 N · 待复习 M」 |
| 置顶开关 | 图钉按钮，状态记在 localStorage |
| 尺寸 | 三档循环（300×170 / 360×220 / 460×300），走 `mini_set_size` |
| 透明度 | 四档（100% / 90% / 78% / 66%），走 CSS opacity —— 比窗口级透明更稳，不会把文字渲染搞花 |

**与主窗口共享词库和学习进度**这件事不需要写同步逻辑：迷你窗与主窗口是同一个进程
里的两个 webview，共用同一个 `AppState` 和同一个 SQLite 文件。

顺带修掉一个真实缺陷：迷你窗与侧边栏如果复用主窗口的背诵槽，**一开小窗就会把主窗口
正在背的那一轮整体覆写**。现在 `session_slot` 认四个槽位（`study` / `review` / `mini` /
`sidebar`），侧边栏此前漏传 `kind` 的写法也一并补上。

## 顺带修掉的两处

- **知识图谱动画收敛**：单击节点不再整图推倒重来（原先会重撒并跑满 320 帧 ≈5.3 秒），
  改为在下方面板显示这个词；阻尼 0.86→0.74、收敛阈值按节点数归一化、拖拽松手才重排。
  交互改为**悬停看释义（气泡跟随鼠标）/ 单击下方看介绍 / 双击按这个词 AI 发散**，
  并删掉 `Detail.openWord` 这个**根本不存在的方法调用**（双击实际永远走跳查词页）。
- **详情卡里的词 chip 点了没反应**：派生词 / 相关词 / 变形 chip 的点击其实执行了查询，
  但结果画在被弹窗遮住的查词页面板里 —— 现在改为**在弹窗内直接打开这个词**，
  本地词库没有时才回退到查词页联网查。

## 已知事项

- AI 自检依赖本地大模型；没部署时按钮会给出明确指路，不会静默失败。
- 语种闸门管的是**书写系统**（日语不会再混进英语表）；英语表里混进一个法语词
  这类同书写系统的问题，由 AI 自检那一层负责。
- 存量清理在**每次启动**自动跑一次；首次升级到本版时如果词库较大，启动会多花一点时间。
