## 二、新窗口跟不上界面语言（本次主要改动）

切到 English 之后，主窗口是英文，而 v0.49 新增的三块界面**整片中文**：

| 界面 | 漏翻规模 |
| --- | --- |
| 迷你悬浮窗（v0.49.0 新增窗口） | 23 条文案里只有 3 条命中 |
| 词图介绍面板 / 状态条（v0.49.0 重做） | 31 条里 0 条 |
| 设置页「词条质量」面板（v0.49.0 新增） | 面板内全部未接入 |

补了 **103 条**英文词条（字典 368 → 471 条）。

### 为什么不能「照源码抄一遍」

字典的键是**渲染后真正出现在文本节点里的字**，而源码里是
`共 <b>${n}</b> 个词 / <b>${n}</b> 条关系` 这种被标签拆散的模板 ——
整段 HTML 从来不会成为文本节点，照抄会得到一条**永远命不中的死键**，
而覆盖率统计照样算它「已翻译」。所以：

- 图例要按碎片建键：`共` / `个词 /` / `条关系`
- 面包屑同理：`以` / `为中心`
- 动态量走模板键：`连接 {n} 条 · 熟练度 {n}% · 词库已收录`

为此新增了 `scripts/check_i18n.cjs` 之外的两道机器检查（见第五节）。

### 一个真错：多占位符的语序

`为「{n}」新增 {n} 条关系` 的英文原写成 `Added {n} relations for “{n}”` ——
回填是按**捕获顺序**来的，不是按语义，于是输出
`Added apple relations for “8”`。改成 `“{n}” gained {n} new relations` 后
语序与捕获顺序一致。这条是被新加的冒烟用例当场抓出来的。

## 三、后端拼好的文案也要跟着界面语言走

前端的翻译是「整段文本查字典」，**够不到字符串内部**。而这两句是后端
拼好直接塞进 JSON 的：

| 文案 | 位置 | 症状 |
| --- | --- | --- |
| `due_text`：「3 天后 / 5 分钟后」 | `cmd_word_state` | 英文界面里出现「下次复习 3 天后」 |
| `interval_text`：「12 小时 / 3 天」 | `cmd_word_state` | 同上 |

改法：`srs` 里新增 `humanize_due_lang(due_at, now, ui_lang)` 与
`ui_lang_is_en(ui_lang)`，`cmd_word_state` 按 `cfg.ui_lang` 输出
（英文 `now / in 5 min / in 3 h / in 2 d`）；`humanize_interval` 同样处理。
判定只写一份，避免「界面选了英文、某个角落还在说中文」这种再也查不干净的散落判断。

`commands/leech.rs` 里那份同名的 `humanize_due` **刻意不动**：它服务的是
Markdown / CSV 导出文件（表头本来就是中文，属导出格式而非界面），
只补了交叉引用注释，免得下次被人当成重复代码合掉。

## 四、迷你窗：「已掌握」提示其实一次都没弹过

```js
// 改前
if (res && res.became_mastered) U().toast(`「${word}」已掌握`, 'ok');
```

`became_mastered` 是 **`ScheduleResult`** 的字段，不在 `AnswerResult` 上 ——
读一个不存在的属性既不报错也不抛异常，界面上唯一的表现是
**这条提示永远不出现**。改为 `res.schedule.became_mastered`。

顺带修掉一处注释里的乱码（`熟��度` → `熟练度`）。

## 五、新增一道常驻检查：`scripts/check_i18n_render.cjs`

`check_i18n.cjs` 回答的是「源码里出现了哪些中文字面量、字典里有没有」，
而界面语言实际是**按文本节点**翻译的，于是它两种错都漏：

| 错法 | 后果 |
| --- | --- |
| **死键** —— 字典里写了整段 HTML（`共 <b>${n}</b> 个词`） | 整段 HTML 从来不会成为文本节点，这条键**永远命不中**，却照样被算作「已翻译」，覆盖率虚高 |
| **漏翻** —— 模板串被标签拆散后真正要建的是碎片键（`共` / `个词 /` / `条关系`） | 碎片在源码里不以字面量出现，字面量扫描**看不见它们** |

新脚本直接跑翻译：加载 `i18n.js`、切成英文、把**渲染后真正会出现的文本**
一条条喂进去（93 条），并附带一条硬约束 —— 严格用例的译文里**不许剩汉字**，
一次抓出所有「翻了一半」。另有 `--gap [文件…]` 模式，按文件列出缺失文案（排查用，不进闸门）。

它已接进 `build.ps1`：冒烟测试之后、编译之前，不通过就中止构建。
理由和冒烟一样 —— 这类错全是**安静**的，不会报错，只会在英文界面里露出来。

其中 5 条标为「宽松」：它们嵌了后端返回的 `e.message`（Rust 侧 `Err("…")`，
本身是中文），包装句必须翻掉，内嵌消息留待后续（见第七节）。

## 六、安卓包终于跟上版本

**根因**：`src-tauri/gen/android/app/tauri.properties` 里写的是
`versionName=0.43.0 / versionCode=43000` —— 这个文件由 CLI 在
`tauri android init` 时生成**一次**，之后 `tauri android build`
不会按 `tauri.conf.json` 刷新它。所以代码早就是 0.49.x，
APK 里装的还写着 0.43.0。

本版把它对齐到 `versionName=0.49.3 / versionCode=49003`
（公式 `major*1000000 + minor*1000 + patch`，与历史值 43000 自洽），
并在文件里留了注释说明「升版本必须手动改这里」。APK 随本版 Release 一起发布。

### `tPattern` 为什么值得改

```js
// 改前：拿「文本里有没有数字」当「可能有插值」的近似判据 —— 两个方向都错
if (!/\d/.test(text)) return text;   // 「取词失败：网络不可用」永远进不来
for (const key of PATTERN_KEYS) { … } // 含数字的普通文本要把全部模板键跑一遍

// 改后：按首字符取候选，一次 Map 查询
const cands = patternByFirst.get(text[0]);
if (!cands) return text;
```

**更快而且不漏**：绝大多数文本首字符不在桶里，直接退出；命中也只跑同首字符的两三条正则。

## 手动验证步骤

1. **新窗口跟随界面语言**：设置 → 界面语言切 English → 托盘菜单或 `Ctrl+M` 呼出迷你窗
   → 标题应是「Review」、按钮是「Know / Don't know」；词图右侧介绍面板
   （点任意词）与设置页「Entry quality」面板也应全英文。
2. **下次复习跟着走**：英文界面下小窗背一个词 → 状态行应是
   `Mastery 40% · Accuracy 75% · Next review in 3 d`（不再出现「3 天后」）。
3. **掌握提示**：小窗连续答对到某词的 `repetitions` 达标 → 应弹出
   「“xxx” mastered」；中文界面下则是「「xxx」已掌握」。
4. **切回中文**：界面语言切回简体中文 → 上述三处必须全部回到中文（不是中英混杂）。
5. **安卓**：安装 APK → 系统「应用信息」里的版本应为 0.49.3。
