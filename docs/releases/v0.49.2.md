# WordWise v0.49.2 —— 迷你窗：修好发音，词条加例句与词组

> 定点修复 + 小窗词条增强，只动迷你窗这一块。
> 发音通路的修复见 `docs/releases/v0.49.1.md`。

---

## 问题（用户截图）

迷你窗里背 `carpet`：

1. **点喇叭不读**（一点反应都没有，也没有报错）；
2. **词条太单薄** —— 只有一条释义 `v. 在…上铺地毯，把地毯铺在…上`，
   没有名词义项（地毯），也没有例句、词组、变形。

---

## 根因

### 1. 喇叭点了没反应：容器上没挂词

发音按钮走的是事件委托，取词是三级回退：

```
按钮自身 data-speak-word  →  最近的 [data-entry-word] 容器  →  最近的 [data-speak-text] 容器
```

`mini.js` 当时只做了 `mn-phon.innerHTML = speakBtn(entry, 'us', '发音')`，
**从没往容器写 `data-entry-word`** —— 三级全空，委托拿到空词直接 `return`：
`if (!word) return;`。所以点下去既不发声也不报错。

详情卡当初踩的是**同一个坑**（`lookup.js` 的 `Detail.open` 里有一段长注释在
警告这件事：音标行不在任何 `[data-entry-word]` 容器里，必须显式写上去），
我在小窗里漏了这一句。

### 2. 词条单薄：只用了后端给的那一条答案串

小窗的释义直接取 `card.answer`（后端按偏好挑出的**一条**义项），
既没用 `entry.senses` 全量，也没渲染例句 / 变形 / 相关词。
而队列里的 `entry` 常常是「占位 / 单薄」的（只有词名和一条释义），
本地库里那条更完整的词条根本没被用上。

---

## 修法

### 发音（`src/js/mini.js`）

- `renderPhon()` 统一渲染音标行：走 `phoneticHtml(entry, { speak: true })`
  （与主界面同一套实现：语言标注、斜杠规则、IPA 字体只有一份）；
- **把词 / 语言 / 音频写到容器上**（`data-entry-word` / `data-speak-lang` /
  `data-speak-audio`），**并且**逐个按钮再挂一份 `data-speak-word`
  —— 两条路都留上，任一条都能取到词。

### 词条内容

| 区块 | 来源 | 说明 |
| --- | --- | --- |
| 释义 | `entry.senses` | **列多条义项**（最多 3 条）；有中文义项时只列中文那组（背英语词时最有用），否则退回原文义项；义项超过 3 条时补一句「…共 N 个义项」 |
| 例句 | `U().collectExamples(entry)` | 最多 2 条，中英对照，**每句可单独朗读**（按钮自带 `data-speak-word`，委托直接读整句） |
| 词组 / 变形 | `entry.inflections` + `entry.related` | 有数据才显示，变形带 label（复数/过去式…），相关词做成 chip |
| 补全 | `#mn-enrich` 按钮 | 词条单薄时就地调后端增强链路（`cmd_enrich_word`）补例句/变形/相关词，完成后自动重渲染 |

另外：出题时若卡片里的词条偏薄，小窗会**按词再查一次本地库**
（`API.getWord`，纯本地、不联网），把更完整的那条换上；后台增强完成
（`enrich://done`）时若正好是当前词，也会自动刷新。

## 手动验证步骤

1. 托盘菜单或 `Ctrl+M` 呼出迷你窗（先确保设置 → 朗读里已装语音包）。
2. **发音**：点单词旁的喇叭 → 应能听到读音；点例句右侧的小喇叭 → 应朗读整句。
3. **词条**：出到 `carpet` 这类词 → 应看到名词 + 动词多条义项、1~2 条中英对照例句、
   变形/相关词 chip；内容多时窗内可滚动。
4. **补全**：找一个明显单薄的词 → 点右上角「补全」→ 提示补全完成后，
   例句/变形出现（需要本地大模型；没部署时会提示去设置页部署）。
5. **回归**：主窗口的发音、以及窗口收起时的发音（v0.49.1 的修复）都不受影响。
