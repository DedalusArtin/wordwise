WordWise 是一款 Windows 桌面背单词软件：左边是干净的词条，右边是本地大模型逐字写出的讲解，答错的词自己钻进错词本、按遗忘曲线准时回到你眼前。前端纯原生 HTML/CSS/JS（无 node_modules），后端 Rust + Tauri 2，离线可用。

> **关于版本号**：GitHub 上目前**只公开发布过 v0.41.0**（2026-10-05）。v0.42.0 只在本机出过包、从未上传，仓库里的 `docs/releases/v0.42.0.md` 是一份未发布的草稿。
> 所以 **v0.43.0 是自 v0.41.0 之后的第一个公开版本**，下面的「本版重点」同时涵盖 v0.42.0 草稿里的改动与本版新增。
> v0.42.0 草稿的原文保留在 `docs/releases/v0.42.0.md`，其中「今日复习统一入口」那一段已被本版的「独立入口」取代，以本文件为准。

## 本版重点

### 1. 安装包语言跟随系统（本版修复）

以前安装向导全程写死中文——在英文系统上照样弹出中文。根因不是 `[Languages]` 段配错（`ShowLanguageDialog=auto` + `LanguageID=$0804/$0409` 一直是对的），而是 **[Tasks] / [Components] / [Icons] 三段和 Code 里 5 处对话框全把中文写死在字面量上**，压根不经过 Inno 的多语言消息机制。

修法：新增 `[CustomMessages]` 段，**42 个键 × 3 份**（`english.` / `chinesesimplified.` / 无前缀全局兜底），三段与 5 处 `MsgBox` 全部改走 `{cm:KEY}` / `ExpandConstant('{cm:KEY}')`。

> 为什么同一段话要写三份：`{cm:KEY}` 的查找顺序是「当前语言前缀 → 无前缀」，没有无前缀那一份时，遇到第三方语言文件（或用户改过 `[Languages]`）就会**取到空串**而不是退化到中文，界面上表现为一串空白按钮。全局兜底不是冗余。

### 2. 图标不再「上圆下方」（本版修复）

图标看起来「歪」是有物理原因的：对 `icon.png`（512×512）做像素级测量，**左右完全对称，但顶部圆角半径 ≈112.5px、底部 ≈97.5px**，差 15px ≈ 3%。大图看不出来，缩到 16px 时上下不对称就放大成了「歪」。另外内容**零留白**（W 顶到画布边缘），小尺寸下四角被切。

修法：重绘全套资源，`R = 105`（取上下圆角的中值）**四角统一**；用「矢量直绘 + 8×8 子采样」而不是面积平均缩放——后者在 512→16 的 32 倍缩小下会把圆角糊掉（实测只剩 1 行渐变，原版是 3 行）。白色 W 用**扫描全图取最亮像素**做参考，逐像素校验：原图白像素 21,731，重绘后仍是 **21,731**，一个不丢。

输出：`icon.png` 512×512、`128x128@2x.png` 256×256、`Square150x150Logo.png` 256×256、`128x128.png` 128×128、`32x32.png` 32×32、`icon.ico`（16/32/48/64/128/256 六档 32bpp PNG）。原图备份在 `.diag/icons-backup/`（本机，不入库）。

### 3. 「按钮写着 1 个词，点进去说一个都没有」——自相矛盾的提示（本版修复）

用户截图里同一屏出现：「开始今日复习（1 词）」「待复习 1」与 toast「今天没有到期的词了」互相打脸。

**真根因是数据**：`study_state` 记录的语言取自**全局设置 `target_lang`**，不是词条自己的语言。用户库里存在一条 `('en', '嗚呼')` 的学习状态，而「嗚呼」这个词条**只存在于 `jlpt-n1`（`ja`）**。于是 `due_states('en')` 数得到它、`get_word('嗚呼','en')` 永远返回 `None`——`build_review_queue` 里 `if let Some(e) = load_entry(...)` 查不到就**静默跳过**，队列变空。界面于是演成「统计数得出来、队列取不出来」。

三层修复：

1. **后端兜底**：新增 `db::get_word_any_lang(word)` —— 按词形取词条、**不限语言**，多条时取释义最完整的那条（`ORDER BY length(entry_json) DESC LIMIT 1`）。`load_entry` 在原有的同语言查询与缓存之后加一级**跨语言兜底**，取不到才返回 `None`。
2. **前端措辞**：`startToday` 里两种「0」分开说——概览上也写着 0 才是「真的没有到期词」（`ok` 提示）；概览写着 N>0 而队列为空，就说「有 N 个词到期，但它们的词条不在当前词库里，已跳过」（`err` 提示）。**不再让两个数字当众打架**。
3. **回归测试**：`get_word_any_lang_falls_back_across_languages` 锁定四条行为——同语言查不到、`get_word_any_lang` 能取到且 `lang == "ja"`、大小写不敏感、真不存在时仍为 `None`。

> 顺带查清并排除的疑点：`ja` 词库按 `rowid` 排序时前 20 条看起来是英语词（`consider` / `efficient`…），一度怀疑词库混入。按 `book_id` 分组核对后确认 `kaoyan-core` 全是 `en`、`jlpt-n1/n2` 全是 `ja`，**词库归属本身是对的**，只是排序顺序误导了判断。

### 4. 「30 天目标 → 预计完成 2028 年」——ETA 的分母取错了（本版修复）

用户报：目标设成 30 天，界面却说**预计 2028-09-29 完成**。

复算一遍就能定位：当时库里剩 **5056** 词，当天背了 **7** 个，旧公式是

```
eta_days = ceil(remaining / today_done) = ceil(5056 / 7) = 723 天
```

——**拿「今天实际背了几个」当长期速率**。当天刚开始背时 `today_done` 还是个位数，除数越小天数越大，早上一打开就显示几百天；反过来深夜背完 100 个，同一本书又会突然说两天就能背完。数字来回横跳，而且和「今日目标」用的公式压根不是同一个口径。

三层修法：

1. **换成分母同源**：新增 `planned_new_per_day(mode, remaining, days_left, per_day)`，把 days / per_day 两种模式的**计划速率**抽成一个函数；`today_target_for`（算今日任务）和 `eta_date`（算完成日）**同一个数**。
2. **`off` 模式返回空串**：没有设目标就不编造日期 —— 原来的写法会拿 0 去除，兜出一个不负责任的结果。
3. **前端措辞同步**：`study.js` 里「按现在的节奏」改成「按当前目标的进度」。数字按计划速率外推，文案却说是「现在的节奏」，自己跟自己打架。

回归测试 3 条：`planned_rate_is_the_eta_basis_not_todays_sample`（分母必须是计划速率）、`eta_never_invents_a_date_without_a_goal`（off 不编日期）、`today_target_and_eta_share_one_rate_function`（两个入口同源）。

### 5. 图标：白色 W 垂直不居中（本版修复）

上一轮修了「上圆角 112.5 / 下圆角 97.5」，但用户截图里图标**看着还是不对**。这次不猜了——先把最小档渲染成 ASCII 逐行看：**白色 W 的包围盒是 y=103..314，中心 208.5，而画布中心是 256，整体上偏了 47.5px ≈ 9.3%**。32px 档上这 9.3% 就是肉眼可见的「歪」。

修法：矢量重绘时按包围盒居中（不是把自己假设的几何中心当准），自检脚本里加了「偏移量 > 1% 画布就报错」的硬门槛。结果：512 档上 W 上下边距 **150 / 150（偏差 0px）**，32px 档 10/10，16px 档 6/6。白色像素数 21,731 → **22,010**（居中后 W 不再被画布边界切掉），多一点是应该的。

> 教训写在这里：上一轮误判的根因是**对着大图靠先验假设**。小尺寸一眼看不出来的问题，反过来也是最容易看错放大倍数 —— 判断图标歪不歪，必须先把 16/32px 档打印成字符逐行读，不能靠肉眼扫 512 图。

### 6. 英语词顶着「日语」标签、切了 piper 却还是系统音色（本版修复）

用户一次报了两件事，看起来毫不相干，**其实是同一个根因**。

只读分析用户真实库（`D:\Projects\test\WordWise\WDATA\wordwise.db`）拿到决定性证据：**`words` 表里 5037 行处于「列的 `lang` 是 `en`、而 `entry_json` 里的 `"lang"` 写着 `ja`」的状态** —— `April` / `significance` / `abdomen` 全在其中：

```json
{"word":"significance","lang":"ja","phonetic":{"uk":"","us":"","audio":""},
 "senses":[{"pos":"","definition":"n. 意义， 重要性"}],"source":""}
```

同一条词在 `dict_cache` 里那份是对的（`lang='en'`、音标 `/sɪɡˈnɪfɪkəns/`）——**错的就是 `entry_json` 里那份**。

**脏数据从哪来**：`db::migrate_words_lang` 搬行时的 SQL 是

```rust
"INSERT OR IGNORE INTO words(word,lang,entry_json,added_at) VALUES(?1,?2,?3,?4)"
//                                            ↑ 列改成了 want，JSON 却原样搬过去
```

语言的两个副本（主键的一半 / JSON 里的字段）从此开始漂移。而**前端读的是 JSON**，于是连锁反应：

| 现象 | 传导路径 |
| --- | --- |
| 英语词显示「日语」标签 | `ui.js` / `lookup.js` 按 `entry.lang` 判定语言标签 → `ja` → 挂蓝色「日语」 |
| 切了 piper 仍是系统音色 | `speak()` 拿 `entry.lang='ja'` 去后端要 piper → `pick_voice_for_lang("ja")` 刻意不跨语言降级，返回 `None` → 报错 → `playLocalTts` 返回 false → 静默回退系统语音 |
| 用户所在地还要加一层 | 这台机器上系统音色只有 7 个（日语 4 + 中文 3），**一个英语的都没有**，所以回退之后照样没声音 |

三层修法：

1. **写入侧掐断源头**：`migrate_words_lang` 搬行时调用 `rewrite_entry_json_lang(&entry_json, want)`，列和 JSON 一起改。坏 JSON 解析不了时原样保留 —— 宁可留着一处语言漂移，也不能把用户的释义一起弄丢。
2. **读取侧兜底**：新增 `entry_from_stored(word, lang, json)`，凡是读出词条的地方（`get_word` / `get_word_any_lang` / `list_words` / `search_words` / `random_words`）**一律以列的 `lang` 为准**覆盖 JSON 里那份。存量清洗要等下一次启动才跑到，没有这层，升级后头几次读取仍然是错的。
3. **存量清洗**：新增一次性幂等迁移 `Db::repair_entry_json_langs()`，启动时紧跟 `fix_builtin_book_langs` 之后运行（顺序不能反 —— 先由它把列改到权威语言，这一步才有一个正确的目标值去对齐 JSON）。

   > SQL 里有一个必须留意的坑：`json_extract` 遇到坏 JSON 会**直接报错让整条语句失败**，一个坏词条就能让迁移整体作废；而 SQLite **不保证 `AND` 的求值顺序**。所以过滤条件写成 `CASE WHEN json_valid(entry_json) THEN … ELSE lang END <> lang`，用 `CASE` 的短路语义兜住。

实测效果已在本机副本上验证：**命中 5037 行、改写 5037 行、第二次运行 0 行**（幂等），释义一字未丢。

回归测试 3 条：`reads_report_the_columns_language_not_the_stale_json_one`（五条读取路径都不能泄漏漂移值）、`language_migration_rewrites_the_json_lang_too`（迁移必须连 JSON 一起改）、`repair_entry_json_langs_aligns_json_and_is_idempotent`（清洗 + 坏 JSON 保护 + 幂等）。

### 7. 语音包分组可折叠；系统音色缺哪门语言要说清楚（本版修复）

- **语音包折叠**：按语言分组之后整页还是太长。现在每组标题是个真 `<button>`（带 `aria-expanded`），**默认只展开「正在学的语言」那一组**；若这门语言压根没有语音包（比如在学韩语而清单里只有英/中），就展开第一组，避免整页只剩一排折叠标题看着像空的。折叠态保留「已装/总数」摘要作线索。点击**就地改 DOM 不重渲染** —— 重渲染会丢焦点，连按几次就没反应了；展开过的组会记住（存在模块级 Map 里），下载完语音包重渲染后不会被合回去。
- **系统音色如实交代**：旧文案是「检测到 7 个系统音色，其中 0 个是神经网络音色」——用户看了只会以为一切正常。现在改成针对**正在学的语言**判断：本机没有就说「本机没有英语的系统语音，朗读英语单词时会没声音或发音不准」，附上「Windows 设置 → 时间和语言 → 语音 → 添加语音」的具体路径，并指向不依赖系统的离线语音包。
- **不再是假装「系统语音」**：`speak.js` 原先在 `pickVoice()` 返回 `null`（一条音色都挑不出来）时照旧上报「系统语音」——界面写着系统语音、耳朵里一点声音都没有。现在如实上报「没有可用语音」，并给出**同会话每种语言只提醒一次**的可操作提示（朗读是高频操作，每次都弹会把人烦死，一次都不说用户就只能对着「点了没反应」干瞪眼）。
- **后端错误文案也说人话**：原先是「没有 en 的本地语音包」，现在换成「本地语音包里没有英语语音，已改用系统语音；可在「设置 → 朗读」下载对应语音包」。

### 11. 背诵

- **今日复习走独立入口，数字不重不漏**：「今日待复习 N」只统计**今天到期（含逾期）**的词。以前把「到期 + 常错」相加，而常错本身就是到期的子集，数字天生偏大——看到 12、点进去却是 20 道题。现在**看到几道就是几道**，复习走自己的会话槽位，取词范围就是那批到期词，**绝不为了凑满「每轮题量」往回捞新词**（只有背诵才补足）。
- **错词攻坚按「连对」出队**：以前用累计答对次数，`对/错/对/错` 这种摇摆也会慢慢把词放走。现在改为**连续答对**才出队，中途错一次立刻重新计数。不在攻坚队列里的词答对了不提示，避免刷屏。
- **全键盘流**：回车立刻进下一题，空格在**任意题型**下都是发音（原来是绑在 `listen_spell` 上的死分支，从来没执行过）。手动抢先与自动推进互斥，不会跳两题。答题计数区新增「连对 N」。答错的词本轮之内真的会再回来一次。
- **选项个数可调**：2～8 个，随题随机打乱。
- **学习目标**：「多少天背完这本书」或「每天背几个」二选一，按公式把**同步复习量**也算进去，给出今天的实际任务与预计完成日期。今天的任务完成弹祝贺卡，也可选「多背一点」——界面如实提示这会让后续复习压力升高。

### 8. 查词与翻译

- **查词结果改成分块卡片**（参照有道）：大词头 + 音标成对紧随其下 + 来源标签，再往下是标签栏，一次只呈现一块（释义 / 变形 / 记忆法 / 相关词）。中文与英英释义分组呈现、虚线分隔。详情卡的「释义」面板**复用同一套渲染**，两处不再分叉。
- **同族派生词**（happy → happiness / happier / happily）：由词形规则生成候选，再**去本地词库确认哪些真的存在**，所以列出来的每一条都点得动、查得到。不联网、不调模型，瞬间返回。只展示真实存在的词是刻意的——凭规则写出 happiness 很容易，但用户点下去发现查不到，比不显示更糟。
- **AI 讲解接了联网检索**：本地词库查不到例句 / 派生变形时，先按需抓一份真实网页资料，把它作为**补充内容的唯一依据**贴进提示词，并在 system 里明确禁止脱离资料编造。讲解顶部如实显示「已联网检索 N 条资料」，来源清单可展开、点击在**应用内**打开。用户关掉「在线搜索」时不会偷偷联网；批量导出讲解刻意不联网（否则等于拿搜索引擎当 API 刷）。
- **翻译不再只给一个主要释义**：`adj. 快乐的；幸福的；愉快的` 这类「词性 + 释义」缩略成一行小卡（**带词性**），默认露 3 条、点开展开全文。
- **在线搜索改为应用内打开**；「权威辞书」那一排跳转仍走系统浏览器——那里的意图本来就是「离开软件去官网看原文」，两处分工是刻意的。
- **语音包按语言分组**：每组显示「已装 / 总数」。**没有本地语音包的语言（日 / 韩 / 阿 / 印）会明确列出并说明原因**：离线引擎（Piper）官方仓库里没有可用音色，仅有的日/韩语音需要 piper 1.7+，而随包引擎是 1.2.0，装上去也报 `"aɪ" is not a single codepoint`，所以宁可不出；朗读会自动改用在线或系统语音。
- **导航 / 标题栏 / 按钮的图标改为内联 SVG**：尺寸与基线全由 CSS 决定（emoji 的字形宽度由平台字体决定，Windows 与 Android 上永远对不齐）。

## Android 版的能力差异（重要）

APK 版本**会降低模型能力**，这不是参数没调好，是平台限制：

| 能力 | Windows | Android | 原因 |
| --- | --- | --- | --- |
| 本地大模型讲解（llama.cpp） | ✅ | ❌ | Android 从 API 29 起禁止 App 执行自己数据目录里的外部二进制（W^X），而 `llama-server` 是 `std::process::Command` 拉起的外部进程 |
| 本地神经语音（piper） | ✅ | ❌ | 同上，piper 也是外部进程 |
| 系统 TTS 朗读 | ✅ | ✅ | 走平台自带 TTS，不受影响 |
| 在线词典查词 / 在线 AI | ✅ | ✅ | 纯网络请求 |
| 词库 / 背诵 / 错词本 / 复习计划 | ✅ | ✅ | 纯本地数据 |
| 多窗口侧边栏 | ✅ | ❌ | 移动端没有常驻窗口的概念 |
| 系统托盘 | ✅ | ❌ | 同上 |
| 便携模式（数据跟随 exe） | ✅ | ❌ | 移动端数据目录由系统分配（应用私有目录） |

界面上，不支持的入口会**明确给出原因**而不是静默失败——静默 `Ok(())` 更糟，界面会以为功能已经生效了。

### 签名（升级安装的前提）

APK 用 `installer/android/wordwise-release.jks` 正式自签名（该密钥与口令**不入库**，见 `.gitignore` 里的说明）：

| 项 | 值 |
| --- | --- |
| 证书主体 | `CN=WordWise, OU=WordWise Android, O=DedalusArtin, C=CN` |
| 别名 | `wordwise` |
| 算法 | RSA 2048 / SHA256withRSA |
| 有效期 | 至 2054-02-21 |
| 证书 SHA-256 | `77:92:63:BE:8B:1D:56:73:78:8A:3A:3B:F2:36:33:52:72:90:6B:29:F7:EA:1D:87:D5:A3:29:17:0B:91:40:1F` |

> **这个密钥必须长期妥善保管（至少两处备份）。** 换密钥后，老版本会被系统判为「签名不一致」而拒绝覆盖安装，用户只能先卸载——而卸载会连词库和背诵进度一起删掉。

签名方案实测：`apksigner verify` 通过 **v2 + v3**（`minSdk 24` 起 v2 即足够，v1 不再需要）。产出不带 `-unsigned` 后缀，可安装。

### 构建侧两个必须记住的坑

1. **`src/lib.rs` 的 `#[cfg_attr(mobile, tauri::mobile_entry_point)]` 不能少。**
   它展开出 `Java_app_tauri_plugin_PluginManager_handlePluginResponse` 等 JNI 胶水符号。漏掉时的表现极具迷惑性：编译**完全通过**、APK **正常产出**，但因为没有导出符号引用 `run()`，链接期 `--gc-sections` 会把整个 tauri 运行时剥光——实测产物只有 **308 KB**、`llvm-nm -D` 输出 **0 行**（正常是 10.4 MB / 24 个 `Java_` 符号），装到手机上启动即闪退。
2. **jniLibs 不再依赖符号链接。** tauri-cli 走 cargo-mobile2，后者是在 `app/src/main/jniLibs/<abi>/` 下建一个指向 cargo 产物的**符号链接**。Windows 建符号链接要开发者模式/管理员权限；更阴的是受限环境会把它**静默降级成 0 字节普通文件**（`ln` 返回 0，日志还照打 "symlinking lib ..."），构建一路绿灯、包里却是空 `.so`。现在 `buildSrc/.../BuildTask.kt` 在 rust 构建后做确定性拷贝，任何权限环境下行为一致。

### 怎么重新出这三个包

```bash
# Windows 安装版 + 便携版（Inno Setup 7 不在 PATH，build.ps1 里用绝对路径调用）
pwsh -File build.ps1

# Android APK（arm64）
source scripts/android-env.sh          # RUSTUP_HOME / CARGO_HOME / ANDROID_HOME / NDK_HOME / JAVA_HOME
cd src-tauri && cargo tauri android build --target aarch64 --apk
# 产物：src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release.apk
```

- **APK 签名密钥**：`installer/android/wordwise-release.jks` + 同目录 `keystore.properties`（两者都已被 `.gitignore` 排除）。
  这两个文件**不在 git 里**，所以换机器时要手动拷过去；丢了就再也签不出可覆盖升级的包。Gradle 找不到它们时**不会报错**，只是产出未签名的 `-unsigned.apk`（装不上），务必留意文件名里有没有 `-unsigned`。
- `build.ps1` 会把 `CARGO_TARGET_DIR` 固定成 `src-tauri\target`，而外部 shell 里它可能是别的值（本机实测是 `D:\Projects\.cargo-target`）。两者都能用，`BuildTask.kt` 关于产物位置的判断同时认这两个。
